# Pi

`llm-prompts install pi` writes everything under `$PI_CODING_AGENT_DIR` where that is set, otherwise `~/.pi/agent`.

## What gets installed

- Rules go into the global `AGENTS.md`, and one file each under `rules/` for agent definitions (see [Roles](#roles)).
- `AGENTS.delegate.md` next to it holds the same rules without the ones whose frontmatter sets `audience: main`. Those rules only apply to the session that talks to the user. Any other `audience` value fails the install.
- [cline-hooks](https://github.com/alexfayers/cline-hooks) is wired in as a pi extension.
- Pi packages listed in `prompts/pi/settings.json`, from core and overlays, are merged into `settings.json` in the agent dir. Pi installs them on startup. Packages you add yourself are left alone. A package can be an object with a `source` and the same `requires_env`, `requires_command` and `requires_absent_command` gates as frontmatter, and is added only where every gate passes.
- `mcp-memory install pi` registers the memory servers in `mcp.json`, which pi's MCP support reads.
- The `CommitGuard` hook blocks a git commit or push until the repository's test command passed on the current files, and a push while the tree has uncommitted changes. The test command is `PI_CONTEXT_TEST_CMD`, or else the one `shared/test-gates.json` detects from the repository's files, with each overlay's gates checked first.
- The `PrimaryCheckoutGuard` hook, in every frontend, blocks an agent command that changes a repository's primary checkout (commit, reset, rebase, a merge or pull without `--ff-only`, push, `gh pr create` and similar), so work happens in a worktree. The exact same command again proceeds.
- The `ShellRules` hook blocks `set -e`, killing processes by port and Docker volume removal.
- Files under `prompts/pi/seed/` are copied into the agent dir only where absent, so they stay yours to edit. A later overlay replaces the same path. For an existing JSON file, seed keys it has never been offered are added once.

## Roles

Each rule is also its own file under `rules/`, and the global `AGENTS.md` holds only the rules for the ordinary lead.

- A rule without `roles` frontmatter, or with `roles: all`, is core and reaches the lead and every agent.
- `roles` can list any of `lead`, `coordinator`, `reasoner`, `worker`, `surveyor`, `reviewer` to limit a rule to those roles. Only Pi reads it. An invalid value fails the install.
- Each generated agent definition starts with one `@../rules/<name>.md` line per rule for its role, and sets `inheritGlobalContext: false`.
- A definition's role is its source's `name`. A source with `rules` gets only those rules, one with `omitClaudeMd: true` gets none, and any other name gets every rule.
- Roles are fixed when an agent starts, so changes apply to new agents.

`llm-prompts check` measures the expanded text of each definition and of the lead as `pi_role_prompt_bytes`. The `collection_bytes` total counts the global `AGENTS.md` and the rule files, not the agent definitions or their expansions.

## Seeded config

| File | Effect |
|---|---|
| `extensions/pi-permission-system/config.json` | [pi-permission-system](https://www.npmjs.com/package/@gotgenes/pi-permission-system) policy. Asks before `git push`, forced or `git -c` git commands, `llm-prompts install/setup/update/uninstall/contribute`, `gh pr` and `gh issue` writes, and edits to rule, skill, workflow and agent files. `promptMaxRows` and `promptFieldMaxWidth` of 1000000 start the prompt fully expanded. |
| `zentui.json` | Turns on only the [pi-zentui](https://www.npmjs.com/package/pi-zentui) statusline: directory, git, model, context, tokens and cost. Change it with `/zentui`. |
| `compact-tools.json` | Draws every tool call in the [pi-compact-tools](https://www.npmjs.com/package/pi-compact-tools) compact style. Change it with `/compact-tools`. |
| `net-guard.json` | `mode` and `allow` list for `net-guard`. `net-guard` warns when the file is missing or cannot be parsed. |
| `context-total.json` | `footer` and `intervalSeconds` for `context-total`. |
| `pane-reaper.json` | `enabled` and `intervalSeconds` for `pane-reaper`. |
| `web-search.json` | Disables the `source_check` tool of pi-web-access. |

## Extensions

These live in `src/llm_prompts/prompts/pi/extensions/`. Each file starts with a `//` header naming its commands, config and env vars.

| Extension | Effect |
|---|---|
| `already-seen` | Replaces a `read`, `grep`, `find` or `ls` result with a short receipt when the same call earlier gave identical output that is still in the model's context. A result whose earlier copy changed or left the context is sent in full. |
| `attic` | Only when a manifest written by `llm-prompts attic build` is readable, at `llmPrompts.attic.manifest` in pi's `settings.json` or else `attic.json` in pi's agent directory: hides the skills and tools it lists, except the pinned ones, from the system prompt and adds one stub line for each. Adds the `unlock` tool, which returns a hidden skill's file text or makes a hidden tool available. The hidden set is saved in the session. Without a readable manifest it does nothing and turns the `unlock` tool off. |
| `cache-miss-notice` | Adds a line to the next tool result after a request that re-writes at least 20000 prompt tokens to the cache, naming the likely cause: a thinking level or model change, a compaction, a context fold, a system prompt or tool list change, or an idle gap past the cache TTL. In a fork, the first request is skipped. |
| `cache-warming` | Keeps the prompt cache warm while a tower-do task this session owns is in progress or a fork run is live, until 2 hours after the last request. Main session only. |
| `cd` | `/cd <dir>` and a `change_dir` tool move the session (history kept) to another working directory. Both refuse while a background fork is still running. |
| `codemode-error-header` | Puts the first error line of a failed `codemode` script in the `Script failed` header. Reading a missing tool name (`tools.foo ? a : b`, `typeof tools.foo`) gives `undefined` instead of throwing, so calling a missing tool fails with a plain `not a function`. Adds a hint for common mistakes and for a script that prints `[object Object]`. |
| `codemode-sleep` | Adds the `sleep` tool: `await tools.sleep({ ms })` in a `codemode` script waits up to 10 minutes. |
| `codemode-wait-until` | Defines `waitUntil(check, { intervalMs, timeoutMs })` at the top of each `codemode` script. |
| `compact-now` | Adds the `compact_now` tool, which compacts the session with a model-written `instructions` summary. |
| `consult` | Adds the `consult` tool. It sends one question and up to 16000 bytes of evidence to an expert in a fresh context, with no tools and no view of the session, at the model's highest thinking level, and returns its answer. The expert is the session's model unless `llmPrompts.consult.model` in `settings.json` names one as `<provider>/<id>`. A larger evidence list, an unavailable model or a failed call is an error result. |
| `context-fold` | Replaces tool results from before the newest 40000 tokens (`CONTEXT_FOLD_KEEP_TOKENS`) with a one-line stub that names a ref for `result_fetch`, in the first request after the prompt cache expired (five minutes, or an hour with `PI_CACHE_RETENTION=long`), once that saves at least 5000 tokens (`CONTEXT_FOLD_IDLE_MIN_TOKENS`), and keeps that fold when the turn completes, so it never rewrites a warm cache. Also replaces an aborted assistant turn from before that point, with its tool results, by one line that names the refs of its results (unless it holds an `ASK:` or `DENIED:` line, or is the last assistant message). Also removes the thinking of every later assistant message and points a `read` receipt for a folded result at the ref. Skips errors, results with `ASK:` or `DENIED:` lines, results under 800 characters and the results of `checkpoint`, `asks`, `ask_user`, `compact_now`, `fork` and `reload_now`. `CONTEXT_FOLD=run-end` also folds when a run ends, once that saves at least 30000 tokens (`CONTEXT_FOLD_PENDING_TOKENS`). `CONTEXT_FOLD_IDLE=off` turns off the fold after the cache expired. If the first request after a fold is rejected, it puts the folded entries back, stops folding for the session and says why. `CONTEXT_FOLD=dry` only records what a run-end fold would fold in a `context-fold` entry, `off` disables it. Not loaded in a delegated session, since a fork's history up to its task is main's cached prompt. |
| `context-total` | `/context-total` reports live context and cost for the session and its forks. `/context-total footer on\|off` toggles a status-line total. |
| `diff-preview` | Shows the pending change of `edit` and `write` calls, and any other ask with a long preview, as a scrollable preview in the permission box. Uses the diff renderer of pi-compact-tools, or pi's own with a one-time warning where that is missing. Scroll with the mouse wheel (fullscreen mode) or `Alt+Up`/`Alt+Down`. |
| `herdr-permission-blocked` | Shows the Herdr "?" state while a permission prompt waits for the user, including prompts forwarded from subagents. |
| `hide-tools` | Hides rarely used LSP and AST tools from the model, and the task board and process tools in non-interactive sessions. `lsp_diagnostics` stays. In the main session, turns `read`, `bash`, `edit` and `write` back on when they are registered but inactive, as after a resume of a session that lost them. |
| `lsp-defaults` | Uses installed `ty` or `ruff` when pyright is absent and no Python server is configured. |
| `mcp-hints` | Helps `codemode` scripts call MCP tools: parses JSON text in results into `structuredContent`, lists tool names once per session, and adds the schema of a tool when a message names it or a script first calls it. Schemas and result shapes are cached in `mcp-hints-cache.json`. |
| `net-guard` | Blocks (`"mode": "block"`) or logs (`"mode": "log"`, to `net-guard.log`) network calls from packages and extensions not in the `allow` list. It wraps `fetch`, the undici dispatcher, `http`/`https` and `net` and attributes calls by stack, so it is best effort and not a security boundary. |
| `pane-reaper` | In a top-level lead running in Herdr, checks on session start and every 60 seconds for processes left by agent panes that are gone, and kills them. Also reports linked worktrees that are safe to remove (clean tree, branch merged into main, unused by any Herdr pane or workspace) but never removes a worktree or branch. `/pane-reaper on\|off` toggles the periodic check. |
| `pending-asks` | Adds the `asks` tool, which pins a question that awaits you in a widget above the editor and removes it once answered. Each `ASK:` line of a tool result that is not an error is also pinned, unless the same ask is already open or the result is from `fork` or `result_fetch`, or the line comes after an `OUTCOME` line, since `pi-context` pins a fork's asks and clears them at the end of the turn. Answering an `ask_user` question removes every ask open before it. `/answer [<id> [<text>]]` (or `ctrl+shift+a`) picks an ask, sends your answer as a message and removes the ask. Every 5 user turns while asks are open, it reminds the model of them in a hidden message. Without a UI, it adds the restate-every-ask rule to the first turn. Main session only. |
| `pi-context` | In a delegated session (`PI_CONTEXT_CHILD` names its handshake file) blocks every tool call the session's role (`reader`, `writer` or `btw`) may not make, MCP and nested `codemode` calls included. A writer's `bash` commands start in its worktree, main-directory paths move to the worktree, and `edit`/`write` outside it are blocked. A bad handshake blocks every call. Adds the `fork` tool, which runs a read-only `reader` delegate on a copy of the session up to the fork call, with the model, thinking level and directory of the session, so the delegate reuses the prompt cache. The call waits for the delegate's reply and returns its outcome line with the cache numbers of the delegate's first request. The full reply is available through `result_fetch`. `role: "writer"` runs a `writer` delegate in a git worktree under `<agent dir>/pi-context/worktrees` on branch `fork/<name>`. A writer without `target` in a primary checkout fails at once, asking to `change_dir` to a worktree first. Another extension can register a worktree provider on `globalThis[Symbol.for("pi-context.worktree-provider")]` that makes and removes that checkout instead, and a writer whose `target` is not a git checkout writes in place there and lands nothing. When it replies, its commits land when they sit on the main checkout's current branch tip, or on `origin/main` with every commit of that tip that `origin/main` lacks (matched by patch or subject), hold no `fixup!`, `squash!` or `amend!` commit and name no private path (the home directory, or a match of the `llmPrompts.forks.privateNames` setting), and the main checkout did not change: the main checkout fast-forwards to them and the worktree is removed. Otherwise the landing escalates to the lead with the reason and keeps the worktree. One landing runs at a time per main checkout and nothing is pushed. `target` names another directory, git checkout or worktree, with `~` and paths relative to the session directory allowed: a reader runs there, and a writer branches from it, lands on its current branch and may not name it, so give each branch its own writer. With `model` the delegate is a cold worker: a fresh session on that model (`provider/id`, optionally `:thinking`) with only the role's skills, the role card appended to its system prompt, `AGENTS.delegate.md` in place of the agent dir's `AGENTS.md`, and no MCP servers of its own. It reaches only the role's MCP tools, through the same socket as the MCP proxy, which is always on for a worker. A cold writer starts in its worktree. It uses the same landing queue. A new cold worker whose model, role and directory match a cold worker still on its first request waits up to 60 seconds for that request to end before it sends its own prompt, so it reads that prompt cache instead of writing the same one again. The widget shows `waiting for cache` while it waits. With `background: true` the call returns at once and the delegate keeps running. A background run's result reaches the session as a `pi-context-results` message that starts a turn as soon as the run ends, or is added when a busy run settles. Each `ASK:` line of the result is pinned as the pending ask `fork-<name>-<run id>-<n>`, and the message names the pins. The pins clear when the main run that got the message settles, unless it was aborted or an `ask_user` call in it was cancelled, timed out or failed. They also clear when `fork_resume` or `fork_steer` names the fork. In a session without a UI (`pi -p`) the session does not finish while a background run is live, for two hours at most. While a background run is live, a widget above the editor shows each one's name, role, elapsed time, turns, `target` when it is not the session directory, and latest tool call or text. A finished background run stays in the widget while its prompt cache is warm, with `cache 3m left`, until main reads a done or found-it result. Each `ASK:` line of a fork's reply is pinned as a pending ask. `fork_cancel` stops a background run by name, and `fork_steer` sends a live one a message that reaches it before its next model call. The runs are saved in the session with any result main has not read yet, so a session resumed after a quit delivers it, and a run that was live when the session ended comes back as lost, naming a reload that ended it and its kept worktree. A writer that ends without landing and leaves its worktree clean, with no commits, loses the worktree and its branch, and `fork_resume` makes them again. A lost run keeps its session file, and `fork_resume <name>` continues it in the background in the same worktree with the same role, model and run id. Only the top-level session can fork. A delegate's environment names its role (`PI_CONTEXT_ROLE`) and its run (`PI_CONTEXT_RUN_ID`). A finished fork (done, found-it, blocked or failed) keeps its session files for 24 hours after it ends. Each run's session is also copied to `<agent dir>/sessions/pi-context/<name>-<run id>.jsonl` when it ends, and that copy is never removed. Then `fork_resume` with a `task` gives it that new task in the background on its own session, model and role. A reader works in its old directory or `target`. A writer works in its kept worktree, or else a new one from the current branch of its checkout. When a finished fork of the same role and directory still has a warm cache, the `fork` result adds a line naming it and its context size. With `mcpProxy: true` under `llmPrompts.forks` in pi's settings a fork starts with `--no-mcp` and runs its MCP calls in the top-level session over a private socket, so no MCP server is started twice. The fork gets proxy tools with the same names, namespaces and exposure, the same active tools and the same `mcp_servers` prompt section. `details.prefix` of a fork result, except a cold worker's, says whether the fork's first request had the same system prompt and tool declarations as the last request of the top-level session, and the result line says `prefix mismatch` when it did not. In the top-level session, `/ghost save <name> [param=value ...]` saves the tool calls of the last run as a ghost under `<agent dir>/ghosts/<repo key>/`, `/ghost list` lists this repository's ghosts, and the `ghost_run` tool replays one without a model call per step, stopping at the first step whose result differs. In the top-level session, `//btw <question>` runs a read-only `btw` delegate on a copy of the session up to its last settled point and stores the answer as a transcript entry that never reaches the model. |
| `permission-box` | Shows the permission prompt as one centred box (92% wide, up to 85% of the terminal height) with the `diff-preview` content above the prompt. A dialog it does not recognise is shown unchanged. |
| `popup-defer` | `/popup-defer on\|off\|<ms>` defers dialogs while you type. |
| `prompt-cache-stabilizer` | Keeps the system prompt unchanged between turns so the prompt cache stays valid, and warns when the system prompt or tool list changes without a new system entry. |
| `result-cap` | Cuts a tool result over 6000 characters (`RESULT_CAP_CHARS`) to its first two thirds of the cap, a marker with a ref, and its last third. A result of 20 or more rows (a JSON list, `grep` lines, paths or `git log` lines) becomes a header with the row count and fields plus its first 20 rows instead, and `grep` results add the top 10 file counts. The `result_query` tool answers questions about such a list by `ref`, with `where` (regex per field), `sort`, `fields`, `count_by`, `limit` and `offset`. The `result_fetch` tool reads the full text back by `ref`, by `offset` and `limit` in characters, or by `pattern` (matching lines). Skips `read`, `edit` and `write`, errors, results with `ASK:` or `DENIED:` lines, and calls made by another tool such as `codemode`. |
| `reload-now` | Adds the `reload_now` tool. Pi runs `/reload` once the agent settles, then sends a message so the agent continues. The tool sends the internal `/reload-now` command, because only a command handler can reload. An aborted run drops the request. A managed Herdsman agent cannot call it. |
| `status-shortcuts` | `/board` lists the in-progress and blocked tasks. Typing `board` on its own does the same, `status` shows the git branch, the open board tasks, the pending asks and the live `fork` runs, and `asks` lists the pending asks. None of them makes a model call. Main session only. |
| `tower-do-patch` | Adds the `tower_do_patch` tool, which changes single tasks on the board. |
| `tower-do-slim` | Re-registers `tower_do`, `tower_do_talk` and `tower_do_status` with shorter descriptions. Moves the board reminder to the next tool result and shortens it to counts, task keys and the full lines of tasks changed since the last reminder. |
| `tower-widget` | Hides the tower-do widget above the editor by default. `/tower-widget` toggles it for the session. |
| `transcript` | Adds the `transcript` tool, which reads the session's own branch, including the entries that folds, `checkpoint` rewinds and compaction took out of the model's context. With no arguments it lists those regions. `around` (an entry id or a checkpoint target) returns the raw entries of the region holding it, and `pattern` (regex) returns the matching entries. Output pages by `offset` and `limit` in characters, 6000 by default. `context-fold` stubs name it. |
| `usage-ledger` | Appends one JSON line per tool call to `usage-ledger.jsonl` in the agent directory: time, session, agent role (also `PI_CONTEXT_ROLE` in a fork), tool, whether another tool made the call, and the path of any `SKILL.md` read. Also loads in child agents. |
